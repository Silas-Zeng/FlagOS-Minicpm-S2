# 硬件与输入驱动的框架探索阶段记录

更新时间：2026-10-21 19:19 UTC（北京时间 10-22 03:19）。本页用于快速接续，不替代原始实验和各方向详细报告。全部设备结果仅属于当前天数 BI-V150，沐曦－曦云 C500 由队友独立负责。

## 实际约束与研究重点

实例为 16 SM、32 GiB、6 CPU 配额、20 GiB 容器内存。长输入时 KV 容量和 prefill/decode 混合执行值得优先处理；不能把整板规格、构造的 D29 几何或单层收益直接当服务瓶颈。官方模型、服务参数与 benchmark 未变；短筛选沿用已保存的原驱动及固定 seed。root 串行持有设备，三位子智能体仅 CPU 准备、资料研究与交叉审阅。

真实覆盖诊断发现前缀外的单 token 请求，因而实现 Attention 内部 compact map，保留外部请求和采样行顺序。KV 诊断实际观测到一次缺页抢占，且没有可先消费以回收 KV 的终止输出，因此不继续实现 terminal drain，也不重复已无收益的 full-output reserve。

KV 四种几何单次往返 wall 分别为 222.053105、235.270289、119.956194、120.716930 ms。计时含主机提交和完成等待，排除显式 setup、毒化及消费者校验区间；但前置 CPU 全字节检查可能影响后续配额调度，当前没有逐窗口 cpu.stat 证据。Event 与 wall 差异不能直接归因为 PCIe、CPU 节流或某个 API。normal 每方向42/336次copy，packed为1/8次；并未实测服务当前采用哪种布局。不能把这四个单样本当稳定带宽或全服务收益。

## 下一项优先工作及停止条件

优先验证实际运行器的 KV tensor 布局与 executor 路径，再设计抢占保存的最小协议：真实先前写入完成→D2H完成确认→原页释放；恢复分配与原zero完成→H2D依赖→原Attention读取。请求epoch、取消、共享页、异常和部分恢复必须有明确处理，不能只改computed或伪造prefix hit。传输模块通过不意味着这套协议已实现。

后续必须比较真实恢复所避免的工作和新增复制/等待成本；13758 token 的既有 exposure 只是保守缺口观测，不是已测重算量。若没有实际缺口、协议挂点无法保证生命周期，或一次必要服务短测无正向信号，应保留反证并暂停该候选。小收益仍保留；只有准备纳入默认时才扩大准确率与官方复现门。
