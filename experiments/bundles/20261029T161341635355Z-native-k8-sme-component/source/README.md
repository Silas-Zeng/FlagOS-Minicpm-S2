# NativeK8 K-SME paired component

CPU preparation for a local producer comparison only. A is the pinned 899ce base CU; B is the exact K-SME lookahead variant. Both are rebuilt as separately named shared libraries and called through the same `ctypes` ABI. They consume one owned 16KiB/page K8 arena and the same original `_reduce_partials` Triton reducer. This component does not inherit main-service qualification, model accuracy status, or official performance status.

Run `python prepare_pair.py` to verify pins and emit isolated sources. On the authorized Linux build host, `python build_pair.py --out /absolute/fresh/path` creates two SOs only; it does not import Torch or initialize a device. After compile/actual-SO ASM review, the device owner may run `worker.py --gpu --root-owned-exclusive --main-root <899ce-source-root> --compiled <build-summary.json> --out <fresh-summary.json>`. The runtime entry hashes both SOs against the successful compile summary before loading them. It does not import the production install wrapper; it AST-loads the pinned original `_reduce_partials` function only.

Exported producer ABI: `query, key_i8, key_scale_full_f32, value_bf16_offset, seq_lens, block_table, batch, scale_log2e, table/q/acc/scalar strides, partial_f32, maximum_f32, summation_f32, stream`. Each arm exports S2 and S4 launchers. The active data is `PAGES * 16384` bytes; typed views point at K code byte 0, full FP32 scale view (K scale entries start at +1024 floats per page), and BF16 V at +4096 BF16 elements. A small redzone beyond the last active page permits the typed V view without changing page addressing.
